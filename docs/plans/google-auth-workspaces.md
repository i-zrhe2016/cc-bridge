## GA-1: Google auth and workspace isolation

### Contract

- Goal: implement the accepted requirement end to end; single Ticket because authentication and resource ownership jointly define the security boundary.
- Ownership: implementation worker owns feature code, tests, dependency/config changes and feature documentation. Coordinator owns this Plan, integration and acceptance decisions. No worker may spawn another worker.
- Dependencies: existing Next.js app and unmodified CCR 3.1.3; no production services or credentials may be modified.
- Interfaces: `/api/auth/[...all]` for Google OAuth/session/logout; `/dashboard` and `/api/workspace` require Google session; retired password workspace session endpoint returns 410. `/v1` restricts each owned key to its own provider/model and filters model listing. `/admin` retains independent operations authentication.
- Persistence: explicit auth schema migration; user/resource ownership in durable SQLite; no production migration during build. User display names may duplicate, internal CCR names remain unique and stable.
- Migration: preview by default, explicit apply to a verified Google account, reject foreign ownership/nonempty target; idempotent retry; preserve CCR data and secrets.
- Non-goals: production publication, domain/DNS configuration, paid plans, organization management, multiple connections per user, passwords or additional identity providers.

### Acceptance

- Real OAuth redirect/callback/state/PKCE/signed identity flow; first registration and returning identity reuse; HTTP-only session, refresh persistence, expiration, revocation/logout, errors and missing-config states.
- Two-user isolation of workspace reads/writes, keys, model requests/listing and usage; forged owner/routing hints cannot cross ownership. Cookie session cannot grant admin access; legacy password cannot grant workspace access.
- Key rotate/revoke/delete semantics, existing JSON/SSE/tools/cancellation behavior, independent admin regression and concurrency behavior preserved.
- Legacy migration preview, apply, repeated apply and rejection cases verified without production writes.
- Typecheck, lint, production build, public browser suite and real CCR integration suite pass; meaningful automatic tests use isolated OAuth/JWKS preload and disposable databases, without production test login bypass.
- Documentation accurately describes implemented/verified behavior, configuration, migration, single-host storage and pending real Google credential validation.
- Fresh independent Sol/high verifier passes the entire same-version Ticket/Plan scope; coordinator retains Test Quality Gate. No implementer re-used as verifier.
